# 历史演示数据说明（2022-09-12 ~ 2026-10-01）

本目录的 SQL 是当前演示库的**完整快照**（表结构 + 数据 + Alembic 版本 0007），用于给农机配件 ERP 提供一套可直接导入、可核对、接近真实业务的历史数据。客户/供应商由 [`scripts/generate_partner_data.py`](../scripts/generate_partner_data.py) 重造并重挂历史订单，[`scripts/reshape_customers.py`](../scripts/reshape_customers.py) 追加 76 户并统一市县/手机号/标签。快照不包含数据库外键，表间按 id 逻辑关联。

## 二、导入前必须确认

1. **先备份目标库**：快照会 DROP 并重建全部表。
2. **不要再先执行 `alembic upgrade`**：快照自带表结构和 `alembic_version=0007`。
3. 只用于本地/演示库，不要导入生产库。
4. 使用 MySQL 8.0；快照包含 JSON 字段和 1,076 个客户、9,329 张销售单。

## 三、DBeaver 导入步骤

1. 连接目标库 `agri_erp`（空库或允许重建的演示库）。
2. 打开 `sql/seed_2022_09_12_2026_10_01.sql`。
3. 使用 **Execute script（执行脚本，Alt+X）**，不要只执行当前语句。
4. 等待执行完成；文件约 10 MB，本机 MySQL 命令行约几秒。
5. 导入后执行下方自检 SQL，核对客户/供应商/订单数量。

命令行等价方式：

```bash
mysql -u erp -p --default-character-set=utf8mb4 agri_erp \
  < sql/seed_2022_09_12_2026_10_01.sql
```

### 实际成交价

- `parts.purchase_price` 是**参考进货价**；
- `parts.sale_price` 是**建议零售价**；
- `purchase_items.price` 是本次实际进货单价；
- `sale_items.price` 是本次实际成交单价（整数元）；
- `sale_orders.total_amount` 是整单实收金额（整数元，多品 = 明细合计，单品 = 单价 × 数量）。

整数化和抹零后，成交价约为建议零售价的 82%~117%，且全部高于商品参考成本；没有低于成本销售。

## 六、时间与时区

- 生成时按 `Asia/Shanghai` 的业务时间排班；
- 写入数据库时统一转换为 **UTC**，与应用存储口径一致；

- 应用接口输出带 `+00:00`，前端会按浏览器本地时区显示。

## 八、导入后自检 SQL

```sql
-- 0. 客户/供应商/订单数量
SELECT COUNT(*) AS customers FROM customers;
SELECT COUNT(*) AS suppliers FROM suppliers;
SELECT COUNT(*) AS sales_orders FROM sale_orders;
SELECT COUNT(*) AS purchase_orders FROM purchase_orders;

-- 1. 库存流水合计 = 配件当前库存
SELECT p.id, p.stock, COALESCE(SUM(l.change_qty), 0) AS log_sum
FROM parts p
LEFT JOIN inventory_logs l ON l.part_id = p.id
GROUP BY p.id, p.stock
HAVING p.stock <> log_sum;

-- 2. 不允许负库存
SELECT COUNT(*) FROM inventory_logs
WHERE before_stock < 0 OR after_stock < 0;

-- 3. 订单金额 = 明细金额合计
SELECT o.id, o.total_amount, SUM(i.price * i.quantity) AS item_sum
FROM sale_orders o
JOIN sale_items i ON i.order_id = o.id
GROUP BY o.id, o.total_amount
HAVING ROUND(o.total_amount - item_sum, 2) <> 0;

-- 4. 日期范围（UTC）
SELECT MIN(created_at), MAX(created_at) FROM sale_orders;
```

### 5.1 价格是怎么定的

没有公开的「杞县零售价目表」，所以按这个口径推：

1. **取电商/批发平台的公开报价**作为基准（京东、淘宝、1688 的同类商品成交价区间）；
2. **加县域零售加价**：整机与水泵按 1.25~1.35 倍，小配件按 1.4~1.5 倍；
3. **反推采购价**：按「零售价 ÷ 1.31~1.45」得到进货价，让毛利率落在 25%~40%，与原有农机配件一致；
4. 单笔成交价在零售价上打 92%~100% 折扣，且不低于成本 × 1.08。

### 5.2 交易流水的生成口径

- 时间范围与原数据一致（2022-09-12 ~ 2026-10-01），交易日落在本地 08:00~18:59；
- 季节性强：春灌（3~5 月）和夏灌（6~8 月）是高峰，冬季几乎不动，
  月份权重见 `scripts/seed_irrigation_data.py` 的 `MONTH_FACTOR`；
- 库存逐笔仿真：低于安全库存自动补货，任何时点库存不为负；
- 每次变动写 `inventory_logs` 的 before/after 快照，与 `parts.stock` 严格对账；
- 销售明细单价取整元，订单总额 = 明细金额之和（与原数据一致）；
- 采购供应商：水泵类走「杞县惠农水泵销售中心」，配件类走「杞县中原农机配件销售中心」；
- **时区**：写入前 `SET time_zone='+00:00'`，落库的就是真实 UTC（本地 08~19 点 → UTC 00~11 点），
  前端按 +8 显示回营业时段。踩过的坑：不设会话时区时，本地 MySQL 的 +08:00 会话会把 timestamp
  再换算一次，导致整批数据偏早 8 小时。

**已知简化**：新增单据没有补 `audit_logs`（原有 16,499 条审计不覆盖这批单据）。
报表、库存、销售记录不受影响；如果在意审计完整性，需要再跑一次补审计脚本。
